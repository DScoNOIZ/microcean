Архитектура: пять слоёв сборки

Система разделена на слои по степени «интеллектуальности» решений. Тяжёлые универсальные модели задействованы только там, где без них не обойтись; массовая работа выполняется лёгкими специализированными компонентами.

СлойОтветственностьМеханизмы
Координация (верхний) Приём задачи на естественном языке; разбиение на под-задачи; разрешение конфликтов между фрагментами; общая координация сборки. Модель высокого уровня (ASI-класса); вызывается точечно, а не для каждой операции.
Рой микро-сетей (средний) Верификация контрактов фрагментов, генерация интерфейсов, оценка пригодности. Множество малых специализированных сетей; активация по типу задачи (принцип sparse MoE).
Эволюционный отбор Подбор комбинаций фрагментов: мутация, скрещивание, отбор по функции пригодности. GA/GP над подмножествами фрагментов; fitness = ошибка + вес + конфликты; схема-теорема Холланда как теоретический фундамент.
P2P-инфраструктура Поиск фрагментов, распространение обновлений, синхронизация состояния без центрального сервера. Kademlia DHT — поиск за O(log n); push-pull gossip — рассылка за O(log n); CRDT — сходимость реплик; rarest-first — репликация редких фрагментов.
Доверие Консенсус и репутация без энергозатратных вычислений. PBFT (3f+1) для совета координаторов; Raft (2f+1) внутри доверенного кластера; hashgraph aBFT как DAG-вариант; репутация = исполняемые тесты + Sybil-защита (Douceur, 2002).

Рабочий цикл сборки

  1. Постановка задачи. Пользователь или агент формулирует требование высокоуровнево: «собери поисковый движок по документам с векторным индексом».
  2. Декомпозиция. Планировщик разбивает требование на классы под-задач: парсинг, хранение, поиск, сетевой протокол, шифрование.
  3. Поиск кандидатов. DHT-запросы находят фрагменты каждого класса: токенизаторы, индексы, TLS-обёртки, AEAD-шифрование.
  4. Эволюционный подбор. Генетический алгоритм перебирает комбинации, отбраковывает несовместимые интерфейсы, развивает жизнеспособные варианты.
  5. Верификация роем. Микро-сети проверяют каждый фрагмент на соответствие контрактам; несоответствующие отбрасываются.
  6. Разрешение конфликтов. Верхний уровень улаживает споры между фрагментами и чинит интеграции.
  7. Финальная сборка и тестирование. Полный прогон тестового набора на собранной программе.
  8. Возврат в сеть. Удачная сборка публикуется обратно как фрагмент — экосистема пополняется.

Путь к прототипу

Первый практический эмбрион уже существует в миниатюре: автоматическое извлечение нужных функций из модулей (code-extraction) вместо подключения пакета целиком. Перенос этого принципа в децентрализованную среду с DHT-реестром фрагментов даёт работающий минимальный прототип Microcean. Оценка этапов: реестр фрагментов + поиск — недели работы; эволюционная сборка на одном языке — следующий квартал; рой верификаторов — параллельная ветка.
